§ 비용

이 세션에 얼마 썼나 — 진짜 숫자로

Claude Code는 세션 기록을 로컬 디스크에 남기고, 거기엔 Anthropic 자신의 usage 데이터(메시지별 토큰·모델)가 들어 있습니다. agent-receipt는 그걸 읽어 리스트 가격으로 환산합니다 — 서버 전송 0·값 저장 0.

긴 세션의 돈은 새 코드가 아니라 매 턴 커지는 컨텍스트를 다시 태우는 데서 나갑니다(위 세션의 80%). 그게 보이면 언제 새 세션을 시작할지 알 수 있습니다. 오늘 누적은 프로젝트의 오늘 세션을 전부 더한 순수 합산 — 월말 청구서가 오기 전에 지금 얼마 쓰는지 보여줍니다. 캐시읽기가 커도 낭비가 아닙니다 — 캐시가 90% 아껴준 것입니다. 지어낸 "절감액" 대신 실측 숫자만.

§ 사고 기록부

무엇을 막아주는가

기능 목록이 아니라, 실제로 벌어지는 사고입니다. 배지는 기계 동작 그대로 — 차단 = 명령 실패(exit 1)·커밋 거부 · 기록 = 증적으로 남음(차단 아님).

📋 AI가 "SOC2 Type II 통과"라고 씀 — 실제론 Type I만 완료

인용문을 출처와 결정론 대조 → 출처에 없는 문장이면 그 자리에서 실패.

CI 차단 · exit 1
🔀 AI가 "커밋 abc가 payment.ts를 수정"이라 씀 — 실제 이력엔 없음

커밋 실재·변경 파일·diff 내용까지 실제 git 이력으로 대조.

CI 차단 · exit 1
📁 AI가 계약 범위 밖 파일을 수정함

허용 경로 계약과 실제 diff를 대조 — 커밋 직전 게이트가 막고, 우회(--no-verify)해도 증거 영수증은 남습니다. guard: block을 켜면 금지 경로 쓰기는 도구 실행 전에 멈추고, 에이전트는 이유를 보고 물러납니다(거부된 시도도 해시체인 기록).

실시간 차단 · opt-in 영수증 기록
🔑 AI가 .env를 읽으려다 실패하고, 외부로 전송을 시도함

git엔 안 보이는 행위 — 실패·거부된 시도까지 행위 종류만 남깁니다(값 미저장). 읽기·전송은 기록만, 실시간 차단 대상은 금지 경로 쓰기뿐(정직한 범위).

⚠ READ_SECRET_FILE   .env  (실패 시도)
⚠ EXTERNAL_NETWORK_CALL   api.exfil.example
기록 — 차단 아님
🔁 AI가 같은 파일을 11번 다시 읽고, 같은 테스트를 4번 반복

capture 로그에서 재계산: 편집 없는 재독 · 동일 명령 반복(본문 미저장·지문만) · 같은 실패 반복. 정상 재확인일 수도 있어 판단은 사람 몫 — 횟수 실측만, 절감 환산은 안 함(측정 불가한 숫자는 표시 안 함).

§ 한 레이어, 두 감사

AI가 한 일과 AI가 한 말

agent-receipt는 AI 에이전트의 코드 작업과 보고서 근거를, 사후에 독립 검증 가능한 증적으로 바꾸는 로컬 감사 레이어입니다. 그 아래 두 서브시스템:

감사답하는 질문
AI 작업 감사
Change Audit		AI가 내 저장소에서 실제로 뭘 했나? 계약 범위 대조 · 해시체인 원장 · 제3자 봉인(Rekor) · git 너머 행위(실패·거부 포함) 기록 — 원하면 실시간 가드(opt-in)로 금지 경로 쓰기를 사전 차단.
AI 근거 감사
Evidence Audit		AI가 말한 근거가 진짜인가? 14종 결정론 검사 — LLM이 LLM을 심사하지 않습니다. 같은 입력이면 언제나 같은 판정.
§ 대상

누구를 위한 제품인가

🏗 AI로 납품하는 에이전시·외주팀

AI가 계약 범위를 넘겼는지, 무엇을 실제로 바꿨는지 — 분쟁 없이 증빙. 클라이언트에 건네는 증거 HTML(share-proof)까지.

📊 AI 리서치·보고서를 의사결정에 쓰는 팀

날조 인용·숫자·버전·커밋 사실이 의사결정에 들어가기 전에 CI에서 차단. 통과분은 영수증으로 축적.

🔐 보안·감사 요구가 있는 내부 개발팀

AI가 읽은 민감 파일·외부 전송 시도·변경 범위를 로컬에 증적화 — 서버·계정 없이, 제3자 공개 로그 봉인(Rekor)까지.

§ 업무 흐름

사용 시나리오

명령 목록이 아니라 업무 흐름입니다.

# 시나리오 A — AI가 만든 보고서를 의사결정에 넣기 전에
agent-receipt research verify --file report.md --out vr/r1.json
#   날조 1건이라도 → exit 1 (CI가 그대로 막음)
agent-receipt graph view --dir vr --out browser.html    # 쌓인 결과 훑기(증거 브라우저)
agent-receipt graph diff --base-dir vr-old --head-dir vr # 신규 실패만 잡는 회귀 게이트

# 시나리오 B — AI에게 코드 작업을 시키고 납품/커밋하기 전에
agent-receipt init --preset generic       # 계약: 건드려도 되는 범위(+ 선택: budget)
agent-receipt policy init --profile strict # (선택) 금지 경로 쓰기를 실행 전 차단
agent-receipt begin                        # 기준점 + 에이전트 지시문
…에이전트 작업…
agent-receipt done                         # 검증 + 검사 + 봉인 작업 영수증
agent-receipt cost                         # 이 세션 실제 토큰 비용
agent-receipt share-proof                  # 클라이언트/감사팀에 건넬 증거 HTML

§ 정직한 경계

이건 무엇이 아닙니다

  • 코드 품질을 보장하는 도구가 아닙니다. 정적 분석·린트·테스트는 다른 도구의 일입니다.
  • 법적 컴플라이언스를 보증하는 도구가 아닙니다. 검토에 쓸 증거를 제공할 뿐입니다.
  • LLM의 추론 품질을 평가하는 도구가 아닙니다. 결론이 옳은지가 아니라 근거가 실재하는지를 봅니다.
  • AI의 모든 행동을 완벽히 감시하는 도구가 아닙니다. 보는 범위와 못 보는 범위를 문서에 명시합니다.
  • 돈을 직접 깎아주는 도구가 아닙니다. 비용은 실제 usage로 정확히 보여주지만 "켜면 30% 절약" 같은 절감액은 약속하지 않습니다 — 어디서 새는지 짚고 멈출 시점을 신호할 뿐, 행동은 사람이 합니다.
  • 대신 — 이 세션에 얼마 썼는지 보여주고, 낭비·이탈을 신호하고, AI 작업과 근거의 "검증 가능한 증적"을 남깁니다.
§ FAQ

자주 묻는 질문

왜 다른 LLM으로 검사하지 않나요?

모델이 모델을 검사하면 "네, 정확합니다"라는 환각을 자기도 낼 수 있습니다. 여기의 모든 판정은 재계산 가능한 산술·문자열·암호 연산 — 같은 입력이면 어느 컴퓨터에서든 같은 답. 그래서 CI 게이트가 됩니다(exit 코드엔 기분이 없습니다).

통과(pass)는 정확히 뭘 보장하나요?

충실성이지 진실이 아닙니다. "주장이 인용한 출처/재계산과 일치한다"는 뜻. 출처 자체가 틀렸다면 충실한 인용도 통과합니다 — 그걸 잡아준다고 말하는 순간이 거짓말이라, 그렇게 말하지 않습니다.

내 데이터는 어디로 가나요?

아무 데도 안 갑니다. 로컬 우선: 계정·서버·텔레메트리 없음. 네트워크는 명시적 옵트인 둘뿐 — --fetch(인용 URL 재확인)와 anchor --upload(영수증 해시를 공개 로그 Rekor에 등록).
