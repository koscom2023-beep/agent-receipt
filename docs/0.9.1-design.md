# agent-receipt 0.9.1 — 실사용 결함 패치 설계/검증 기록

> 0.9.0 publish 후 Promptia dogfooding 에서 확인된 **실제 결함만** 고친 긴급 패치. 기능 확장 아님.
> 동결: `verify --json` 14키 · `output.ts` JsonReport 키 · `run-fixtures.ts` SPEC_KEYS · contract/session/policy 스키마 ·
> 새 의존성 0 · package-lock 변경 0 · 자동 git/publish 0.

## 배경 (dogfood 에서 잡힌 것)

- `agent-receipt --version` → `모르는 명령: --version` / 계약 없으면 `계약서 경로가 필요함`. 버전 확인 불가.
- `doctor` 가 "어느 바이너리/버전을 실제로 쓰는지 + npm latest" 를 안 보여줘서 global 0.8.1 ↔ local 0.9.0 혼선 발생.
- `next` 가 verify FAIL 시 "위반 1건" 만 말해 원인이 안 보임.
- 정찰 종료 시 `.agent-guard/audit-packs/` 등 도구 산출물이 close-recon 을 막지 않는지 확신 부족.

## 14인 회의 (정·반·합 — 요지)

1. **CLI 계약가**: `--version`/`-v`/`version` 셋 다, 계약·git 탐색 **이전**, help·unknown **이전**에 처리. → main() 최상단 단일 분기.
2. **빌드 엔지니어**: 버전 SSOT = `package.json`. 하드코딩 상수 두면 bump 때 두 곳 수정 → 누락. → `import.meta.url` 로 `../package.json` 읽기(dist/src 동일 경로). 실패 시 `"unknown"`(throw 금지).
3. **악마의 대변자(네트워크)**: doctor 가 `npm view` 를 매번 호출하면 **golden 비결정/오프라인 실패**. → **반론 수용**: `AGENT_RECEIPT_NO_NET=1` 로 조회 생략(capture-golden ENV 에 주입). 네트워크 실패는 **advisory** 로만, doctor exit code 불변.
4. **테스트 결정론자**: doctor 출력의 휘발 라인(실행 파일 경로·현재 버전)은 normVolatile 로 `<BIN>`/`<VER>` 정규화. 버전 bump·clone 경로에 무관하게 golden 안정.
5. **회귀 가드(악마의 대변자)**: "close-recon 이 audit-packs 때문에 실패한다" 는 가설. → **검증으로 반증**: `runVerify` 가 `isToolOutput` 으로 unstaged/staged/untracked 를 이미 필터(`checks.ts`), `buildReceipt`→`runVerify` 라 close-recon clean-gate 도 이미 안전. 실제 dogfood 실패 원인은 `.gitignore`(진짜 사용자 파일) 였음 — **올바른 거동**.
6. **합의(보강)**: 코드 거동은 이미 맞으나 (a) `*.sig.json`/`*.approval.json` 사이드카를 경로 무관하게 명시 추가, (b) "audit-packs untracked → exit 0 / 진짜 untracked → exit 1" 을 **임시 repo 회귀 테스트**로 못박는다. close-recon 본체는 무수정(이미 정확).
7. **next 설계가**: next 핵심은 여전히 "한 명령 추천". FAIL 요약은 **짧게**(counts 5종 + 대표 파일 3개) 덧붙이고 끝은 `다음: explain`. 자동 수정/reset/commit 절대 없음. `verify --json` 구조 불접촉(next 가 새로 출력만).
8. **문서가**: 실사용 검증은 **global/npx latest** 기준(dogfood 원칙). local `dist` 직접 호출은 개발자 내부 검증일 뿐. `.gitignore` 권장 블록은 README+template 에 명시하되 **init 은 .gitignore 를 자동 수정하지 않는다**(안내만).
9. **호환성 심사역**: 14키·JsonReport·SPEC_KEYS·스키마 무변경. doctor/init/version 만 출력 표면 변경 → golden 재캡처는 **해당 케이스만**(doctor ×3, init ×5, 신규 ×4). verify/close-recon/next-PASS golden 불변 확인.
