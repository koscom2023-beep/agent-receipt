## 1. 14인 전문가 회의

각 전문가 1라운드(정) → 2라운드(반론/정반합). 악마의 대변자(E14)는 범위축소를 강하게 주장.

### 1라운드 — 정(thesis), 전문가별 입장

1. **CLI/UX 설계자** — 신규 6명령은 기존 `begin/done/commit-check/audit-pack` 동사 관습과 일치. `--kind`는 `--cursor/--claude`와 같은 플래그 자리. 발견가능성 위해 `help --all`에 그룹 추가 필수.
2. **세션/생명주기 아키텍트** — `kind`는 `SessionData` optional 필드가 정답. recon↔implementation 경계가 세션에 기록돼야 close-recon이 "구현 세션 자동 reset" 사고를 막을 수 있다. baseline "exists" 문구는 "그대로 사용"이 오도의 근원 — 전환 시 reset 강제 표현 필요.
3. **14키 동결 수호자** — kind/linked/mode/modeClaims/externalActions **그 무엇도** `toJsonReport`에 넣지 마라. 전부 session.json·receipt sidecar·신규 명령 stdout. fixtures 5케이스는 한 글자도 안 건드린다.
4. **계약/스키마 설계자** — `linked_test_paths`/`expected_linked_tests`는 zod `.optional()` 또는 `.default([])`. 기존 계약(필드 없음)이 깨지면 안 됨 → `.default([])`. PolicySchema.mode는 `.default("standard")`.
5. **정책 모델러** — measure_first/observe_only는 **자동 검출 불가**(AI call·DB write·studioLog는 git diff로 안 보임). 정직하게 "self-report + 체크리스트"로만. 도구가 "측정 전용 보증"을 한다고 착각시키면 정체성 붕괴.
6. **감사/증거 전문가** — no-code 정찰을 audit-pack에 묶으려면 notes/decisions를 `buildAuditPack`이 수집해야. decision receipt에 headHash 박아 "어느 커밋 시점 판단인지" 고정.
7. **보안/안전선 담당** — prepare-commit/finish는 **git을 절대 실행 안 함**. heredoc EOF와 `agent-receipt reset`이 한 줄에 붙는 복붙사고 → 블록 물리 분리. denied/outOfScope 있으면 커밋블록 출력 자체를 막아라.
8. **테스트 엔지니어** — 신규 명령 전부 golden 케이스화. 비결정성(타임스탬프/스탬프파일명/경로)은 `norm`/`normTs`로. close-recon은 reset까지 하므로 "session 삭제됨" 확인 산출물 캡처. core 추출은 기존 golden 불변이어야 검증됨(회귀 가드).
9. **release-check/git 전문가** — `git rev-list base..HEAD`·`diff --name-only base...HEAD`로 충분. risk class는 **휴리스틱임을 명시**(거짓확신 금지). rollbackBase=base 해시. test 교집합은 `--failed-tests` 파일 줬을 때만, 없으면 "검증 안 함" 명시.
10. **self-report/정직성 전문가** — modeClaims/externalActions는 출력에서 **git-검증가능 / self-report / 검증불가** 3구역 분리. 절대 섞지 마라. LIMIT_NOTE 일관 스탬프.
11. **DX/실사용자(dogfood)** — 진짜 통증은 둘: (a) 정찰 세션 안 닫고 baseline 유지, (b) 복붙 한줄붙음. close-recon·prepare-commit이 이걸 직접 해결하면 가치 큼. `next` 한 명령 추천도 매 턴 "지금 뭐하지" 제거.
12. **문서/온보딩 담당** — README/CONTRACT/recipes 최소 갱신. 신규 명령은 `help --all`에 한 줄씩. 과한 문서는 학습비용↑.
13. **하위호환/마이그레이션 담당** — ★"정의됐을 때만 출력" 원칙으로 기존 session/contract/policy/golden 전부 불변 유지. 0.8.1 사용자 업그레이드 시 동작 안 바뀜.
14. **악마의 대변자** — *반대*: (a) 10기능은 과욕, 명령만 늘고 루프가 더 복잡. (b) finish는 done+commit-check+audit-pack+prepare-commit 4개를 묶어 실패지점 추적이 어려움 — 차라리 빼라. (c) modeClaims/externalActions는 self-report라 "감사 도구가 거짓 보고를 증거화"하는 모순. (d) note 명령은 git commit 없이 증거를 만든다 = "git이 유일한 진실" 정체성과 충돌. (e) release-check risk class는 거짓확신 양산.

### 2라운드 — 반(antithesis) → 합(synthesis)

- **악마의 대변자(a) 과욕** 반박(세션아키텍트+DX): 6신규명령 중 4개는 기존 core 재사용(추가코드 적음), kind/linked/mode는 기존 명령 *표시 강화*다. 단 **수용**: finish는 "modify"로 — 단계별 PASS/FAIL과 실패지점을 명시 출력해 추적성 확보.
- **악마의 대변자(b) finish** 반박(CLI/UX+테스트): finish는 dogfood 최다요청. **합의**: finish 유지하되 각 단계 결과를 라벨로 출력(done✓/commit-check✗ 등) + 실패 시 "다음 한 명령" 안내. 자동 git 절대 금지.
- **악마의 대변자(c) modeClaims 모순** 반박(self-report 전문가+감사): 도구는 "보증"이 아니라 "기록 + 한계고지". **합의**: modeClaims/externalActions는 **claim에 있을 때만 표시**, 항상 "self-report(검증불가)" 라벨 + LIMIT_NOTE. buildPrompt 필수 JSON은 **안 바꾼다**(AI 출력 부담↑·prompt golden churn 회피) — 고급 사용자 opt-in 필드로 문서화.
- **악마의 대변자(d) note=git 우회** 반박(감사+정체성): note는 git을 우회하는 게 아니라 **"코드 변경 0인 판단"도 증거로 남기는** 것. 정체성과 충돌 안 함 — 단 notes/decisions는 `isToolOutput`으로 verify에서 제외(=사용자 작업물 아님 명시)하고, decision receipt에 headHash를 박아 "이 커밋 시점의 판단"으로 고정. **합의**: 채택, `note` 단일 명령(`receipt --type`로 오버로드 안 함).
- **악마의 대변자(e) risk class 거짓확신** 반박(release-check 전문가): **수용**. risk class는 매 줄 "휴리스틱 — 커밋 제목 기반 추정" 명시, 점수화 금지(사실/분류만). `notVerified` 구역에 "교집합 미검사" 등 한계 적시.
- **14키 수호자(2라운드)**: 모든 합의가 sidecar 원칙 지킴 확인. 단 **F5 linked test 함정** 적시 → prepare-commit이 "linked test만 oos면 커밋블록 허용"하는 UX는 verify 판정을 바꾸지 않음을 코드주석+golden으로 못박아라.
- **하위호환 담당(2라운드)**: receipt.session.kind는 "정의시만" 스프레드 → s6 golden(=`start` 무kind) 불변 재확인.

### 악마의 대변자 판정 (수용/기각)
- 수용: finish 추적성 강화(modify), risk class 휴리스틱 명시, modeClaims/externalActions는 표시전용·prompt 불변.
- 기각: 10기능 축소(전부 dogfood 통증 직격), finish 삭제(최다요청), note 삭제(증거가치 > 정체성 우려, isToolOutput로 해소).
