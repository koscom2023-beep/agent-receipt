# 벤치 하네스 — 검사기의 정밀·재현율 + 재현성을 숫자로

**풀려는 문제.** "결정론 검사기가 실제로 나쁜 주장을 잡나? 몇 %나? 그리고 같은 입력이면 **정말** 매번 같은 판정인가?" — 도구가 이걸 스스로 숫자로 증명하지 못하면, 신뢰는 말뿐이다.

**이 예제가 보여주는 것.** `agent-receipt bench` 는 **gold 라벨이 달린 주장셋**에 검사기를 걸어

- **혼동행렬**(TP/FP/FN/TN)과 **정밀·재현율·F1·정확도** — positive class = `failed`(나쁜 주장 포착),
- **재현성**: 각 주장을 N회 돌려 판정+지문이 **매회 동일한가**

를 출력한다. 판단·모델 호출 0.

## 실행

```bash
agent-receipt bench --file examples/bench/citeseed.json --repeat 5
#   재현성 위반(같은 입력이 다른 판정)이면 exit 1 → CI 가 막는다
echo "exit=$?"
```

이 시드셋(12건)의 기대 결과:

| 지표 | 값 | 뜻 |
|------|-----|-----|
| 재현성 | **12/12 · 60 평가 전부 동일** | 같은 입력 → 같은 판정(결정론) |
| TP / FP / FN / TN | 5 / 1 / 0 / 6 | 환각 5건 전부 포착, 의역 1건 과잉거절 |
| 정밀 / 재현율 | **83.3% / 100%** | 나쁜 주장은 다 잡되, 의역에 false alarm 1 |
| 정확도 | 91.7% | 12건 중 11건 gold 일치 |

**FP 1건은 의도된 정직함이다.** 11번 주장은 뜻이 같지만 리터럴 인용이 아니라(의역), 엄격한 grounding 검사가 `failed` 로 잡는다 — 이건 결함이 아니라 [rag-grounding](../rag-grounding/README.md) 에서 말한 **문자열 대조의 성질**이다. bench 는 그 대가(정밀 100%→83.3%)를 숨기지 않고 **측정**한다.

## 왜 재현성이 핵심인가

LLM 이 LLM 을 심사하는 평가(RAGAS·Braintrust 등)는 같은 입력에도 판정이 흔들린다(2024~2026 학계: 편향·순위 뒤집힘·temp0 도 비재현). 이 검사기는 순수함수라 **재현성 100% 가 자명**하지만 — bench 는 그걸 **게이트**한다. 누군가 검사기에 `Date.now()`·난수·맵 순서·부동소수 비결정을 흘리면, bench 가 `exit 1` 로 즉시 잡는다. 재현성은 자랑이 아니라 **불변식 회귀가드**다.

## 정직한 경계 (중요)

- **gold 라벨은 객관 근거**(부분문자열 여부·재계산·해시·스키마)지 주관 판정이 아니다 — LLM-eval 의 주관 rigging 과 다르다.
- 이 시드셋 정확도는 **표본내·표본력 없음**(12건). **"세계 정확도"가 아니다.** 외부 공개 데이터셋(CiteAudit 등)은 **같은 입력 문법**으로 그대로 붙는다(후속).
- **LLM-judge 와의 정확도 비교는 하지 않았다.** bench 가 대비 주장하는 건 오직 **재현성**(같은 입력→같은 판정)뿐이다. "더 정확하다"는 측정 없이 말하지 않는다.
