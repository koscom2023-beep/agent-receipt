# RAG 답변 근거 검증 (Grounding / Faithfulness)

**풀려는 문제.** RAG 시스템은 문서를 검색해 컨텍스트를 모은 뒤 LLM 이 답변을 생성한다. 문제는 LLM 이 **검색된 컨텍스트에 없는 것을 지어낸다**는 것이다(환각). "SOC 2 Type I 을 완료했다"는 근거를, 답변은 슬쩍 "Type II 를 통과했다"로 격상시킨다. 이 **근거 충실성(grounding/faithfulness)** 을 사람이 매번 대조하면 RAG 파이프라인을 신뢰할 수 없다.

**이 예제가 보여주는 것.** `agent-receipt` 는 답변의 각 주장을 **검색된 컨텍스트와 결정론으로 대조**한다. 답변 문장이 컨텍스트에 실재하면 verified, 없으면 not-found — LLM 에게 "이거 맞아?"라고 되묻지 않는다.

이 예제의 답변 주장 4건 중 2건은 근거가 있고, 2건은 환각이다:

| 답변 주장 | 검색 컨텍스트 | 결과 |
|-----------|--------------|------|
| SOC 2 **Type I** 감사 2026년 3월 완료 | 있음 | ✅ verified |
| 데이터센터 서울·도쿄 | 있음 | ✅ verified |
| **SOC 2 Type II 를 통과** | 컨텍스트는 "Type I 완료·Type II 미시작" | ❌ **환각 반려** |
| **직원 500명** | 컨텍스트는 240명 | ❌ **환각 반려** |

## 실행

```bash
agent-receipt research verify --file examples/rag-grounding/answer-claims.md
#   환각 2건이 걸려 종료코드 1 → RAG CI/eval 게이트가 그대로 막는다
echo "exit=$?"
```

## 어떻게 작동하나

각 주장의 `quotedText`(답변에서 뽑은 문장)가 `sourceFile`(검색된 컨텍스트)에 **문자 그대로**(공백 정규화 후 부분문자열) 존재하는지 본다. 존재하면 근거 있음, 없으면 환각. 판단·모델 호출 0.

## 정직한 경계 (중요)

이 검사는 **문자열 대조지 의미 대조가 아니다.** 답변이 컨텍스트를 *의역*해서 뜻은 같지만 문장이 다르면 not-found 로 잡힌다 — 이건 결함이 아니라 **엄격한 grounding 검사**의 성질이다. 벡터 검색·임베딩·의미 유사도는 하지 않는다. 즉 이 도구는 "답변이 검색 컨텍스트에 **문자 그대로 근거하는가**"라는 재현 가능한 하한선을 지키고, 의미 수준 평가(LLM-judge·의미 유사도)는 그 위에 얹을 별도 층이다. 두 가지를 **섞지 않는 것**이 이 도구의 방식이다 — 결정론으로 확정할 수 있는 것만 결정론으로 본다.

## 시장 맥락

RAG 평가(faithfulness)는 LLMOps·AI-eval의 핵심 주제다(Braintrust·Langfuse·RAGAS 등은 대개 **LLM-judge** 방식). 이 예제는 그 옆에 서는 **결정론·비-LLM·재현 가능** 층이다 — 같은 입력이면 어느 컴퓨터에서든 같은 판정이라 CI 게이트가 된다. KPMG·EY 가 찾는 RAG·AI 거버넌스에도 그대로 붙는다.
