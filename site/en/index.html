The 60-second catch

The classic quiet upgrade — "Type I completed" becomes "Type II passed". Real output, verbatim (the CLI prints in Korean; exit codes and JSON are language-neutral).

$ agent-receipt research verify --file report.md --out vr/r1.json

    quote: completed a SOC 2 Type I audit in March 2026  → verified

14 deterministic checks

One kernel registry — the code is the spec (agent-receipt spec --format json). Every verdict is recomputable arithmetic, string, or crypto.

kindverifies
citationthe quote is literally in the cited source
numbera stated number exists in the source, or matches a recomputation (sum/mean/ratio…)
dateformat-agnostic date match ("Mar 1, 2026" ≡ "2026-03-01")
hash / signatureSHA-256 integrity · real Ed25519 verification (non-repudiation)
commit / fileChanged / diffContains"commit X exists / changed file Y / its diff contains Z" — against actual git history
schema / versionJSON-Schema subset conformity · real semver-range satisfaction (^3.23.8 ⊨ 3.24.0)
file / artifacta claimed path exists · a build output matches declared shape constraints (size bounds / sha)
receipta cited receipt exists and its seal replays clean — fabricated receipt references are mismatches
linkURL well-formedness — advisory only, never counted as evidence

Quick start

# install
npm install -g @promptia-labs/agent-receipt

# Track A — work receipts (in a git repo)
agent-receipt init --preset generic     # contract: what the agent may touch
agent-receipt begin                     # baseline + paste-in agent instructions
…the agent works…
agent-receipt done                      # verify + check + sealed Work Receipt

# Track B — verify what the agent *said* (no git needed)
agent-receipt research verify --file report.md --out vr/r1.json
agent-receipt graph view --dir vr --out browser.html   # Evidence Browser
agent-receipt graph diff --base-dir vr-old --head-dir vr   # exit 1 on new failures

FAQ

Why not just have another LLM check the first LLM?

A model checking a model can hallucinate its own "yes, that's accurate." Every verdict here is recomputable arithmetic/string/crypto — same input, same answer, on any machine. That's also why it works as a CI gate: exit codes don't have moods.

What does a pass actually guarantee?

Faithfulness, not truth. A pass means the claim matches its cited source / recomputation. If the source document itself is wrong, a faithful citation still passes — claiming otherwise would be a lie, so this tool doesn't.

Where does my data go?

Nowhere. Local-first: no account, no server, no telemetry. The only network calls are explicitly opt-in: --fetch (re-fetch a cited URL) and anchor --upload (register a receipt hash to the public Rekor transparency log so third parties can verify without trusting you).

How is this different from permission hooks?

Hooks prevent, receipts prove. Permissions stop an action before it happens; agent-receipt produces after-the-fact, tamper-evident evidence of what actually landed — including gate bypasses (--no-verify still leaves an evidence receipt), failed attempts, and permission-denied attempts.

Is this a compliance product?

No. It provides git-based evidence relevant to review (mappable to control families via controls) — it never asserts compliance.
