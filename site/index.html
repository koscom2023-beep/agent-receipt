검증 영수증(JSON)을 떨어뜨리면 봉인(contentHash·receiptId)을 이 자리에서 재계산합니다. 파일은 브라우저 메모리에서만 읽습니다(업로드 0). 샘플 영수증 내려받기 → 떨어뜨려보고 → 메모장에서 한 글자 고쳐 다시 떨어뜨려보세요(변조 검출 체험).

날조 인용·숫자·버전·커밋 사실이 의사결정에 들어가기 전에 CI에서 차단. 통과분은 영수증으로 축적.

🔐 보안·감사 요구가 있는 내부 개발팀

AI가 읽은 민감 파일·외부 전송 시도·변경 범위를 로컬에 증적화 — 서버·계정 없이, 제3자 공개 로그 봉인(Rekor)까지.

하나의 레이어, 두 개의 감사

agent-receipt는 AI 에이전트가 남긴 코드 작업과 보고서 근거를, 사후에 독립적으로 검증 가능한 증적 체계로 바꾸는 로컬 감사 레이어입니다. 그 아래 두 서브시스템:

감사답하는 질문
AI 작업 감사
(AI Change Audit)		AI가 내 저장소에서 실제로 뭘 했나? 계약 범위 대조·해시체인 원장·제3자 봉인(Rekor)·git 너머 행위(실패·거부된 시도 포함) 기록.
AI 근거 감사
(AI Evidence Audit)		AI가 말한 근거가 진짜인가? 14종 결정론 검사 — LLM이 LLM을 심사하지 않습니다. 같은 입력이면 언제나 같은 판정.

사용 시나리오

명령 목록이 아니라 업무 흐름입니다.

# 시나리오 A — AI가 만든 보고서를 의사결정에 넣기 전에
agent-receipt research verify --file report.md --out vr/r1.json
#   날조 1건이라도 → exit 1 (CI가 그대로 막음)
agent-receipt graph view --dir vr --out browser.html    # 쌓인 결과 훑기(증거 브라우저)
agent-receipt graph diff --base-dir vr-old --head-dir vr    # 신규 실패만 잡는 회귀 게이트

# 시나리오 B — AI에게 코드 작업을 시키고 납품/커밋하기 전에
agent-receipt init --preset generic     # 계약: 건드려도 되는 범위 선언
agent-receipt begin                     # 기준점 + 에이전트에게 줄 지시문
…에이전트 작업…
agent-receipt done                      # 검증 + 검사 + 봉인된 작업 영수증
agent-receipt share-proof               # 클라이언트/감사팀에 건넬 증거 HTML

14종 결정론 검사

커널 레지스트리 하나에 등록 — 코드가 곧 스펙(agent-receipt spec --format json).

종류검증 내용
citation인용문이 출처에 실제로 있나
number주장한 수가 출처에 있거나 재계산(합계·평균·비율…)과 일치하나
date표기가 달라도 같은 날인가("Mar 1, 2026" ≡ "2026-03-01")
hash / signatureSHA-256 무결성 · 진짜 Ed25519 전자서명 검증
commit / fileChanged / diffContains"커밋 X가 존재/파일 Y 변경/그 diff에 Z 포함" — 실제 git 이력 대조
schema / versionJSON 스키마 부분집합 정합 · 진짜 semver 범위 충족(^3.23.8 ⊨ 3.24.0)
file / artifact주장한 경로 실재 · 빌드 산출물이 선언한 형태(크기/해시)와 정합
receipt인용한 영수증이 실재하고 봉인 재계산까지 통과
linkURL 형식만 — 참고용, 증거로 안 침

날조 패턴 모음

각 카드는 플레이그라운드에서 실시간으로 판정됩니다.

📋 조용한 격상"1형 완료" → "2형 통과" — citation not-found 🔢 숫자 슬쩍 바꿈출처는 52%, 주장은 58% — number mismatch 📅 날짜 슬쩍 바꿈3월 1일이 4월 1일로 — 형식 무관 대조 📦 버전 슬쩍 올림선언은 ^1.4.0, 주장은 2.0.0 — 진짜 semver 판정 🧩 필수 필드 누락설정에 required 키 없음 — 경로까지 짚어줌 🧮 합계 재계산11+14+16은 정말 42 — 믿는 게 아니라 계산

이건 무엇이 아닙니다

  • 코드 품질을 보장하는 도구가 아닙니다. 정적 분석·린트·테스트는 다른 도구의 일입니다.
  • 법적 컴플라이언스를 보증하는 도구가 아닙니다. 검토에 쓸 증거를 제공할 뿐입니다.
  • LLM의 추론 품질을 평가하는 도구가 아닙니다. 결론이 옳은지가 아니라 근거가 실재하는지를 봅니다.
  • AI의 모든 행동을 완벽히 감시하는 도구가 아닙니다. 보는 범위와 못 보는 범위를 문서에 명시합니다.
  • 대신 — AI 작업과 AI 근거에 대해 "검증 가능한 증적"을 남깁니다.

자주 묻는 질문

왜 다른 LLM으로 검사하지 않나요?

모델이 모델을 검사하면 "네, 정확합니다"라는 환각을 자기도 낼 수 있습니다. 여기의 모든 판정은 재계산 가능한 산술·문자열·암호 연산 — 같은 입력이면 어느 컴퓨터에서든 같은 답. 그래서 CI 게이트가 됩니다(exit 코드엔 기분이 없습니다).

통과(pass)는 정확히 뭘 보장하나요?

충실성이지 진실이 아닙니다. "주장이 인용한 출처/재계산과 일치한다"는 뜻. 출처 자체가 틀렸다면 충실한 인용도 통과합니다 — 그걸 잡아준다고 말하는 순간이 거짓말이라, 그렇게 말하지 않습니다.

내 데이터는 어디로 가나요?

아무 데도 안 갑니다. 로컬 우선: 계정·서버·텔레메트리 없음. 네트워크는 명시적 옵트인 둘뿐 — --fetch(인용 URL 재확인)와 anchor --upload(영수증 해시를 공개 로그 Rekor에 등록).
