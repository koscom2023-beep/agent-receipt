# agent-receipt — 지금까지 만든 기능 전체 목록 (2026-07-02 기준)

> ⚠️ **역사 스냅샷(2026-07-02·v0.14 시점)** — 현행 기능 목록이 아닙니다. 현행은 README와 `help --all`이 정본입니다.


> 이 문서는 실제 코드(`agent-receipt help --all`)를 그대로 확인해서 작성했습니다 — 기억이나 추측이 아니라 실제 존재하는 명령 기준입니다.
> 버전: `0.14.0`

agent-receipt는 크게 **두 개의 독립된 트랙**으로 이루어져 있습니다.

- **Ⅰ부. Work Receipt 트랙** — "AI가 git 저장소에 실제로 뭘 했는지"를 증명(git이 유일한 증거)
- **Ⅱ부. Verification Engine 트랙** — "AI가 말한 근거가 진짜인지"를 증명(git과 무관·주장 대 출처 대조)

두 트랙은 완전히 다른 종류의 영수증(schemaVersion이 다름)을 만들고, 서로 섞이지 않습니다.

---

## Ⅰ부. Work Receipt 트랙 (git 기반 증거)

### 세션 생명주기

1. **`begin`** — 작업을 시작할 때 현재 git 상태(baseline)를 찍어둡니다. 나중에 "작업 시작 전과 후 뭐가 바뀌었나"를 비교하는 기준점입니다.
2. **`done`** — 작업 종료 시 검증(verify)+대조(check)를 한 번에 돌리고 결과를 영수증으로 저장합니다. 핵심 루프의 마지막 단계.
3. **`next` / `finish` / `start` / `status` / `mode` / `reset`** — 세션 상태를 조회·전환·초기화하는 보조 명령들(지금 어느 단계인지, 무슨 모드인지 확인).
4. **`close-recon`** — "정찰(조사)만 하고 코드는 안 건드렸다"는 걸 얼릴 때 쓰는 명령 — 정찰 단계와 구현 단계를 구분해서 기록합니다.

### 계약(Contract) — 무엇이 허용 범위인지 미리 정의

5. **`init --preset <name>`** — 프로젝트에 맞는 계약서(무엇을 건드려도 되는지 규칙)를 프리셋으로 생성. `presets`로 목록 확인 가능.
6. **`draft-contract`** — 계약서 초안을 자동 생성.
7. **`review` / `lint` / `doctor`** — 계약서 자체를 검토·문법 검사·건강 진단.

### 실제 검증(git 실측 — 이 도구의 핵심)

8. **`verify`** — git diff가 계약서 규칙(허용된 파일/경로/패턴)을 지키는지 실측 대조. **PASS/FAIL의 근거는 오직 git**입니다.
9. **`check`** — verify와 함께 도는 보조 대조 단계.
10. **`claims --file <c.json>`** — AI가 "나는 이런 파일만 건드렸다"고 자기보고한 내용을 실제 git 변경사항과 대조 — 자기보고와 실제가 다르면 잡아냅니다.
11. **`pre` / `prompt`** — 커밋 전 사전 점검, 그리고 AI 에이전트(Cursor/Claude 등)에게 줄 지시문 생성.

### git 훅 자동화

12. **`install-hooks` / `uninstall-hooks`** — `pre-commit`(위반 시 커밋 차단)·`pre-push`(푸시 전 게이트)·`post-commit`(증거 기록 — `--no-verify`로 게이트를 우회해도 증거는 남음) 훅을 자동 설치.
13. **`selftest`** — 임시 저장소를 만들어서 "차단이 실제로 작동하는지, 우회했을 때도 증거가 남는지"를 스스로 검증합니다(설치가 제대로 됐는지 확인용).

### 영수증(Receipt) 생산·이력

14. **`receipt` / `receipts`** — 검증 결과를 정식 영수증 파일로 저장·목록 조회. `--committed` 옵션으로 "게이트를 우회했어도 커밋 자체는 기록"이 가능.
15. **`commit-check`** — 커밋 직전 게이트(훅이 내부적으로 이걸 호출).
16. **`trailer`** — 커밋 메시지에 검증 결과를 자동으로 덧붙이는 기능.
17. **`ledger (rebuild|verify)`** — 모든 영수증을 해시체인으로 엮은 원장. 한 줄이라도 순서를 바꾸거나 지우면 체인이 깨져서 바로 티가 납니다(변조 탐지).

### 감사(Audit)·보고 묶음

18. **`audit-pack`** — 여러 영수증을 하나의 감사용 묶음으로 압축.
19. **`report [--type developer|client|audit]`** — 대상(개발자용/고객용/감사용)에 맞게 형식이 다른 보고서 생성.
20. **`audit`** — 누적 영수증 통계 요약(전체 개수·pass/fail·민감 경로 건드린 횟수 등).
21. **`share-proof`** — 외부(고객 등)에 그대로 전달할 수 있는 독립 실행 HTML 증거 파일 생성. 핵심 루프 3단계 중 마지막.

### 읽기 전용 분석 계층 (판단 아님·집계만)

22. **`insights [--since <n>]`** — 누적된 영수증에서 로컬로 뽑아내는 패턴 분석(예: 자주 위반되는 규칙이 뭔지).
23. **`risk`** — "AI 작업 자체"의 위험 신호(범위 이탈·미검토 상태로 수용된 변경·민감한 행위 등)를 표시. **부채 점수화가 아니라 신호 표시**입니다.
24. **`controls`** — 감사 프레임워크(예: 통제 항목)에 이 도구가 만드는 증거를 매핑해서 보여줌.
25. **`dashboard` / `index`** — 누적 상태를 한눈에 보는 정적 화면.
26. **`incident`** — 사고(문제)가 생겼을 때 최근 영수증들을 조사하는 용도. **자동 복구는 안 합니다** — 조사만.

### 무결성·서명·제3자 증명

27. **`replay [--pack <dir>] [--receipt <p>]`** — 저장된 영수증을 다시 계산해서 "이 영수증이 진짜 그 시점에 그 내용으로 만들어졌는지" 재검증(자가 변조 탐지).
28. **`attest`** — 증명(attestation) 생성.
29. **`anchor [--upload]`** — 영수증 해시를 **Sigstore Rekor**(제3자 공개 투명성 로그)에 등록. 이후엔 "내 컴퓨터를 안 믿어도" 남이 직접 그 공개 로그에서 확인할 수 있습니다 — 자가보고를 넘어서는 유일한 층.
30. **`keys init` / `sign` / `verify-signature` / `approve` / `approvals`** — 로컬 ed25519 키로 영수증에 서명하고, 사람이 승인(approve)한 이력을 남기는 흐름.

### 정책(상시 규칙)

31. **`policy init --profile <solo-founder|vibe-coder|agency-client|team-strict|promptia>` / `policy check` / `policy show`** — 프로젝트 성격에 맞는 표준 규칙 묶음을 적용·점검.

### Capture — git 너머의 행위 추적 (alpha)

32. **`capture install/uninstall`** *(0.13.0: 서브에이전트(Task)·MCP 호출·실패 시도까지 이름만 기록 — 지시문/인자는 값이라 저장 안 함)* — 에이전트의 툴 호출(Read/Bash 등) 훅을 설치해서, git에는 안 보이는 행위(비밀파일 읽음·외부 네트워크 호출 등)를 기록.
33. **`capture show` / `capture verify` / `capture reset`** — 기록된 행위 목록 확인, 체인 무결성 검증(변조 여부), 초기화. **값 자체는 저장 안 하고 행위 종류만** 기록(예: "어떤 파일을 읽었다"는 남기되 내용은 안 남김).

### Advisory — 참고용(검증 아님·PASS/FAIL 근거 아님)

34. **`release-check --base <ref>`** — 배포해도 되는지 판단을 도와주는 참고 자료(배포 자체는 안 함).
35. **`note --type <recon|contract-draft|no-code-decision|next-options>`** — 사람이 남기는 메모(git으로 검증되는 게 아니라 표시만).
36. **`policy mode measure_first|observe_only`** — 강제가 아닌 self-report 체크리스트 모드.
37. **`claim modeClaims|externalActions`** — self-report(자기보고) — git으로 검증이 안 되는 종류의 주장.

### 연동 (experimental — 아직 실제 전송은 안 함)

38. **`export --format slack|json|github-pr|otel|langfuse`** — 영수증을 다른 시스템 형식으로 변환(미리보기 단계).
39. **`gen-claim --transcript <jsonl>`** — 에이전트의 실제 대화 기록(transcript)을 읽어서 검증용 `claim.json`을 자동 생성 — 이후 `claims`로 대조 가능.

## Ⅱ부. Verification Engine 트랙 (2026-07-01~ 신설 — "AI가 한 말이 진짜인가")

Work Receipt 트랙이 "AI가 파일을 어떻게 바꿨나"를 본다면, 이 트랙은 "AI가 조사했다고 주장한 내용·회의에서 근거로 든 내용이 실제로 사실인가"를 봅니다. **LLM이 LLM을 검사하지 않습니다** — 전부 결정론(같은 입력엔 항상 같은 결과) 코드로 대조합니다.

### Evidence Kernel — 핵심 검증 엔진

40. **15종 결정론 검사** (`evaluateClaim`) — 하나의 "주장"에 딸린 근거를 아래 15가지 방식으로 대조:
    - **citation** — 인용문이 출처에 실제로 있나(부분문자열 대조)
    - **number** — 주장한 숫자가 출처에 있거나, 재계산(합계·평균·비율 등)과 실제로 일치하나
    - **range** — 주장한 숫자가 명시한 상·하한 [min, max] 안에 드나(경계 포함)
    - **date** — 날짜가 형식이 달라도(예: "Jan 5, 2026" vs "2026-01-05") 같은 날인지 확인 후 출처와 대조
    - **hash** — 내용의 SHA-256 등 해시값이 주장과 일치하나(진짜 암호학적 계산)
    - **signature** — 내용이 진짜 그 공개키로 서명됐나(Ed25519 전자서명 검증)
    - **link** — URL 형식이 맞나(참고용 — 이것만으로는 증거로 안 침)
    - **commit** *(0.13.0 신규)* — 주장한 git 커밋 해시가 저장소에 실재하나
    - **fileChanged** *(0.13.0 신규)* — 그 커밋이 실제로 이 파일을 바꿨나
    - **diffContains** *(0.13.0 신규)* — 그 커밋의 diff에 실제로 이 내용이 있나
    - **schema** *(0.13.0 신규)* — 데이터가 정해진 JSON 구조(타입·필수필드·enum 등)를 만족하나
    - **version** *(0.13.0 신규)* — 패키지 버전이 의존성 파일의 범위 표기(^ ~ 등)를 실제로 충족하나
    - **file** *(0.13.0 신규)* — 주장한 파일이 디스크에 실재하나
    - **receipt** *(0.13.0 신규)* — 인용한 검증 영수증이 실재하고 봉인 재계산까지 통과하나
    - **artifact** *(0.13.0 신규)* — 빌드/테스트 산출물이 선언한 형태 제약(크기 경계·해시)과 정합하나(빈/절단 산출물 검출)

### research / council verify — 실제 사용 진입점

41. **`research verify --file <report.json|report.md>`** — 조사 보고서(JSON 또는 동결 문법 마크다운) 안의 주장들을 위 15종 검사로 대조. 날조된 인용이 하나라도 있으면 `exit 1`(자동화 파이프라인에서 진짜 게이트로 씀). `--fetch`는 URL을 실시간으로 다시 가져와 독립 재대조(네트워크 사용).
42. **`council verify --file <decision.json> [--log <path>]`** — 회의(멀티 에이전트 토론 등)에서 내린 **결정의 근거**를 같은 방식으로 대조. 날조된 근거로 내려진 결정을 "ungrounded"로 잡아냄. **회의 자체를 실행하진 않습니다** — 이미 내려진 결정을 검증만.
43. **`--out <path>` (두 명령 공통)** — 검증 결과를 정식 **Verification Receipt**로 봉인 저장(입력 해시+출처 구분 포함).

### Evidence Specification

44. **`spec [--format json]`** — 이 검증 포맷 자체를 사람이 읽는 요약 또는 기계가 읽는 JSON Schema로 공개. "코드가 곧 스펙"이라 실제 검사 목록과 항상 일치.

### Evidence Graph / Evidence Browser — 쌓인 결과 활용

45. **`graph query`** — 쌓인 영수증을 조건(커밋/입력/모델/영수증ID)으로 필터링해서 조회.
46. **`graph view [--out <html>]`** — **Evidence Browser**(자체완결 정적 HTML — 서버 없이 브라우저로 바로 열림). 대시보드 → 실패 목록(체크별/모델별/주제별/커밋별/이유별) → 이유·증거 → 영향받은 주장 → 영수증(맨 마지막)순으로 구성. 같은 결과가 반복 검증되면 자동으로 하나로 접혀서(occurrences) 표시됩니다.
47. **`graph failures`** — 실패만 골라서 우선순위별로 훑어보는 트리아지 화면.
48. **`graph diff`** — 두 시점(또는 두 디렉터리)을 비교해 "새로 생긴 실패"를 찾음. **신규 실패가 있으면 exit 1** — CI 파이프라인에서 회귀 방지 게이트로 사용 가능.
49. **`graph history`** — 특정 주장(지문)·입력·주제의 시간에 따른 변화 이력(언제 처음 등장했고, 언제 무엇이 바뀌었나).
50. **`graph subjects`** — 프로젝트(주제) 단위로 pass/fail·실패 유형을 롤업한 상태판.

### 부가 장치

51. **주장 지문(fingerprint, `cfp1:`)** — "같은 주장"을 시간이 지나도 같은 것으로 인식하게 해주는 식별키(문장+출처+검사종류 기반 해시). 이 덕분에 이력 추적(`graph history`)이 가능합니다.
52. **검증됨(verified) vs 자가보고(reported) 등급** — 이 도구가 직접 재계산/재확인한 사실만 "verified"로 표시하고, 나머지(모델 이름, 커밋 해시 등 자기보고 항목)는 "reported"로 명확히 구분 — 자가보고를 검증된 사실처럼 세탁하지 않습니다.
53. **SDK 배럴** (`import from "@promptia-labs/agent-receipt"`) — CLI뿐 아니라 라이브러리로도 직접 가져다 쓸 수 있게 공개 표면을 정리(Stable=계약 유지 대상 / Provisional=바뀔 수 있음 두 등급으로 명시 구분).

## 최근에 특히 새로 고친 것들 (2026-07-02 하루)

54. **결과 중복 제거(fold)** — 같은 결과를 반복 검증하면 파일은 여러 개 쌓이지만 화면에는 "진짜 다른 결과"만 보이게 수정(전에는 반복이 서로 다른 문제처럼 보이는 결함이 있었음).
55. **Evidence Browser 시각 재설계** — 한국어 우선 표기, 큰 글씨, 눈에 편한 배경색(순백 대신 톤 있는 연회색), 상태색은 작은 표시로만 절제해서 사용.
56. **git 사실 기반 검사 5종 신설**(위 40번 항목의 신규 5개) — "숫자·문자열 대조 몇 개"라는 지적을 받고 실제 git 이력 대조 능력으로 확장.
