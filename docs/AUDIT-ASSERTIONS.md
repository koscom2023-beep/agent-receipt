# 검사 ↔ 감사 어사션 매핑

agent-receipt 의 결정론 검사는 재무제표 **어사션(assertion)** 과 **내부통제** 개념에 자연스럽게 대응한다. 감사·회계 실무자가 이 도구를 평가할 때 참고하도록, 그 대응을 정리한다. 판정은 전부 산술·문자열·암호 연산이라 같은 입력이면 어느 컴퓨터에서든 같은 답이 나온다 — 즉 **감사인이 재수행(re-perform) 가능**하다.

## 검사 → 어사션 → 통제 개념

| 검사 kind | 재무제표 어사션 | 통제·감사 개념 |
|---|---|---|
| `citation` | 실재성·발생 (Existence/Occurrence) | 증빙 대사 — 주장의 근거가 원문에 실재하는가 |
| `number` (재계산) | 정확성·평가 (Accuracy/Valuation) | 재수행(Recalculation) — 합계·차이·비율을 다시 계산 |
| `date` | 기간귀속 (Cutoff) | 거래가 옳은 기간에 기록됐는가 |
| `hash` | 완전성 (Completeness) | 데이터 무결성 — 기록이 변조되지 않았는가 |
| `signature` | 권리와 의무·권한 (Rights/Authorization) | 승인·진본성·부인방지 (Ed25519) |
| `commit`·`fileChanged`·`diffContains` | 실재성·완전성 | 변경통제 — "무엇이 언제 바뀌었나"를 원장(git)과 대조 |
| `schema`·`version` | 정확성·표시와 공시 | 데이터 품질(DQM)·의존성 정합 |
| `file`·`artifact`·`receipt` | 실재성 | 산출물·증빙의 실재와 봉인 재계산 |

## 통제 유형별

- **예방통제 (Preventive).** `guard: block` 을 켜면 금지 경로 쓰기를 도구 실행 *전에* 차단한다 — 오류가 기록되기 전에 막는다.
- **탐지통제 (Detective).** 위 검사들은 이미 만들어진 산출물을 사후에 대조해 불일치를 드러낸다(불일치 → exit 1).
- **감사증적 (Audit Trail).** 모든 판정은 해시체인 원장에 append-only 로 남고, 봉인(contentHash·receiptId) 재계산으로 **변조탐지(tamper-evidence)** 가 된다.
- **재수행 가능성 (Re-performance).** 결정론이라 감사인이 같은 입력으로 판정을 그대로 재현할 수 있다 — LLM 이 LLM 을 심사하는 방식이 못 주는 성질.

## 대차평균의 원리 예시

복식부기의 대차평균(차변합계 = 대변합계)은 `number` 검사의 `diff` 재계산으로 표현된다: `차변합계 − 대변합계 = 0`. 실제 시연은 [`examples/audit-journal-entry`](../examples/audit-journal-entry/) — AI 가 생성한 분개 4건 중 불균형 1건과 날조 근거 1건을 결정론으로 반려하고(exit 1), 결과를 봉인해 변조를 탐지한다.

## 정직한 경계

이 매핑은 검사의 **성격**을 감사 언어로 옮긴 것이지, agent-receipt 가 법정 감사기준을 충족한다는 뜻이 아니다. 도구는 근거의 **실재·정합**을 결정론적으로 확인할 뿐, 계정과목 선택의 적정성이나 거래의 실질 같은 **판단**은 감사인의 몫이다 — 이 도구는 그 판단에 쓸 재현 가능한 증거를 만든다.
