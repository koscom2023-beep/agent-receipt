agent-receipt

AI 작업 영수증. 에이전트가 실제로 한 일 — 그리고 에이전트가 말한 것이 진짜인지.
두 가지를 기계로 증명합니다: 저장소에서 벌어진 일(작업 영수증)과, 보고서 속 근거의 진위(검증 영수증).
브라우저에서 커널 돌려보기 → 증거 브라우저(Evidence Browser) 데모
npm install -g @promptia-labs/agent-receipt
지금 바로 날조 잡아보기 (브라우저 안에서만 실행 — 서버 전송 0)

🧾 남이 준 영수증, 설치 없이 검사 — 여기 끌어다 놓으세요

Verification Receipt(JSON 파일)를 떨어뜨리면 봉인(contentHash·receiptId)을 이 자리에서 재계산합니다. 파일은 브라우저 메모리에서만 읽습니다(업로드 0). 샘플 영수증 내려받기 → 떨어뜨려보고 → 메모장에서 한 글자 고쳐 다시 떨어뜨려보세요(변조 검출 체험).

60초 데모

고전 수법 — "1형(Type I) 완료"가 "2형(Type II) 통과"로 슬쩍 격상. 실제 실행 출력 그대로입니다.

$ agent-receipt research verify --file report.md --out vr/r1.json

[2] Acme has passed a SOC 2 Type II audit
    인용 : has passed a SOC 2 Type II audit  → not-found

1   # 읽어야 아는 보고서가 아니라, 진짜 CI 게이트

git 너머 — 실패한 시도까지

git에는 깔끔한 한 줄 diff만 보입니다. 같은 세션이 비밀 파일을 읽으려다 실패했고, 외부로 전송을 시도했다면? 실제 출력 그대로 — 값은 저장하지 않고 행위 종류만 남깁니다.

14종 결정론 검사

커널 레지스트리 하나에 등록 — 코드가 곧 스펙(agent-receipt spec --format json). 전부 재계산 가능한 산술·문자열·암호 연산입니다.

종류검증 내용
citation인용문이 출처에 실제로 있나
number주장한 수가 출처에 있거나 재계산(합계·평균·비율…)과 일치하나
date표기가 달라도 같은 날인가("Mar 1, 2026" ≡ "2026-03-01")
hash / signatureSHA-256 무결성 · 진짜 Ed25519 전자서명 검증(부인 방지)
commit / fileChanged / diffContains"커밋 X가 존재/파일 Y 변경/그 diff에 Z 포함" — 실제 git 이력 대조
schema / versionJSON 스키마 부분집합 정합 · 진짜 semver 범위 충족(^3.23.8 ⊨ 3.24.0)
file / artifact주장한 경로 실재 · 빌드 산출물이 선언한 형태(크기 경계/해시)와 정합
receipt인용한 영수증이 실재하고 봉인 재계산까지 통과 — 지어낸 영수증 인용은 불일치
linkURL 형식만 — 참고용, 증거로 안 침

각 카드는 플레이그라운드에서 실시간으로 판정됩니다 — 커널이 당신의 브라우저에서 직접.

바로 시작

# 설치
npm install -g @promptia-labs/agent-receipt

# 트랙 A — 작업 영수증 (git 저장소 안에서)
agent-receipt init --preset generic     # 계약: 에이전트가 건드려도 되는 범위
agent-receipt begin                     # 기준점 + 에이전트에게 줄 지시문
…에이전트 작업…
agent-receipt done                      # 검증 + 검사 + 봉인된 작업 영수증

# 트랙 B — AI가 *말한 것* 검증 (git 불필요)
agent-receipt research verify --file report.md --out vr/r1.json
agent-receipt graph view --dir vr --out browser.html   # 증거 브라우저
agent-receipt graph diff --base-dir vr-old --head-dir vr   # 신규 실패=exit 1

자주 묻는 질문

왜 다른 LLM으로 검사하지 않나요?

모델이 모델을 검사하면 "네, 정확합니다"라는 환각을 자기도 낼 수 있습니다. 여기의 모든 판정은 재계산 가능한 산술·문자열·암호 연산 — 같은 입력이면 어느 컴퓨터에서든 같은 답. 그래서 CI 게이트가 될 수 있습니다(exit 코드엔 기분이 없습니다).

통과(pass)는 정확히 뭘 보장하나요?

충실성이지 진실이 아닙니다. 통과는 "주장이 인용한 출처/재계산과 일치한다"는 뜻. 출처 문서 자체가 틀렸다면 충실한 인용도 통과합니다 — 그걸 잡아준다고 말하는 순간이 거짓말이라, 그렇게 말하지 않습니다.

내 데이터는 어디로 가나요?

아무 데도 안 갑니다. 로컬 우선: 계정 없음·서버 없음·텔레메트리 없음. 네트워크는 명시적 옵트인 둘뿐 — --fetch(인용한 URL 재확인)와 anchor --upload(영수증 해시를 공개 투명성 로그 Rekor에 등록 — 남이 당신을 안 믿어도 검증 가능).

권한 훅(hook)과 뭐가 다른가요?

훅은 막고, 영수증은 증명합니다. 권한은 행동을 사전에 차단하고, agent-receipt는 사후에 변조-감지 증거를 남깁니다 — 게이트 우회(--no-verify)에도 증거는 남고, 실패한 시도·거부된 시도까지 기록합니다.

컴플라이언스 제품인가요?

아닙니다. 검토에 쓸 수 있는 git 기반 증거를 제공할 뿐(controls로 통제 항목에 매핑 가능) — 규정 준수를 보장한다고 절대 말하지 않습니다.
