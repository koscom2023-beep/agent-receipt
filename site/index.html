14 deterministic checks · 14종 결정론 검사

One kernel registry — the code is the spec (agent-receipt spec --format json). 전부 재계산 가능한 산술/문자열/암호 연산.

kindverifies
citationthe quote is literally in the cited source · 인용문이 출처에 실재하나
numbera stated number exists in the source, or matches a recomputation (sum/mean/ratio…) · 재계산과 상등
dateformat-agnostic date match ("Mar 1, 2026" ≡ "2026-03-01")
hash / signaturesha-256 integrity · real Ed25519 verification (non-repudiation)
commit / fileChanged / diffContains"commit X exists / changed file Y / its diff contains Z" — against actual git history · 실제 git 이력 대조
schema / versionJSON-Schema subset conformity · real semver-range satisfaction (^3.23.8 ⊨ 3.24.0)
file / artifacta claimed path exists · a build output matches declared shape constraints (size bounds / sha)
receipta cited receipt exists and its seal replays clean — fabricated receipt references are mismatches
linkURL well-formedness — advisory only, never counted as evidence

Quick start · 바로 시작

# install
npm install -g @promptia-labs/agent-receipt

# Track A — work receipts (in a git repo)
agent-receipt init --preset generic     # contract: what the agent may touch
agent-receipt begin                     # baseline + paste-in agent instructions
…the agent works…
agent-receipt done                      # verify + check + sealed Work Receipt

# Track B — verify what the agent *said* (no git needed)
agent-receipt research verify --file report.md --out vr/r1.json
agent-receipt graph view --dir vr --out browser.html   # Evidence Browser
agent-receipt graph diff --base-dir vr-old --head-dir vr   # exit 1 on new failures

FAQ

Why not just have another LLM check the first LLM? · 왜 LLM으로 검사하지 않나요?

A model checking a model can hallucinate its own "yes, that's accurate." Every verdict here is recomputable arithmetic/string/crypto — same input, same answer, on any machine. That's also why it can be a CI gate: exit codes don't have moods.

What does a pass actually guarantee? · 통과는 뭘 보장하나요?

Faithfulness, not truth. A pass means the claim matches its cited source / recomputation. If the source document itself is wrong, a faithful citation still passes — the tool never pretends otherwise. 출처 자체가 틀린 건 못 잡습니다(그걸 잡는다고 주장하는 순간이 거짓말이라서).

Where does my data go? · 데이터는 어디로 가나요?

Nowhere. Local-first: no account, no server, no telemetry. The only network calls are explicitly opt-in: --fetch (re-fetch a cited URL) and anchor --upload (register a receipt hash to the public Rekor transparency log so third parties can verify without trusting you).

How is this different from permission hooks? · 권한 훅과 뭐가 다른가요?

Hooks prevent, receipts prove. Permissions stop an action before it happens; agent-receipt produces after-the-fact, tamper-evident evidence of what actually landed — including gate bypasses (--no-verify still leaves an evidence receipt) and failed attempts.

Is this a compliance product? · 컴플라이언스 제품인가요?

No. It provides git-based evidence relevant to review (mappable to control families via controls) — it never asserts compliance. Wording in the tool is deliberately limited to "evidence relevant to / supports".
