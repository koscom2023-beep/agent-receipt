Two independent tracks · 두 개의 독립 트랙

Each produces its own tamper-evident receipt. 각 트랙이 서로 다른 종류의 변조-감지 영수증을 만듭니다.

TrackQuestion it answers
Work ReceiptWhat did the AI actually do to my git repo? Contract-scoped diff evidence, hash-chained ledger, third-party Rekor anchoring, action capture beyond git (secret-file reads, network calls, failed attempts).

60-second catch · 60초 데모

The classic quiet upgrade — "Type I completed" becomes "Type II passed". Real output below (verbatim). 실제 실행 출력 그대로입니다.

$ agent-receipt research verify --file report.md --out vr/r1.json

[1] Acme completed a SOC 2 Type I audit in March 2026
    인용 : completed a SOC 2 Type I audit in March 2026  → verified
[2] Acme has passed a SOC 2 Type II audit
    인용 : has passed a SOC 2 Type II audit  → not-found
    ✗ FAIL — 근거가 출처와 불일치(날조/수치·날짜오류)
결과: verified 1 · FAIL 1 · advisory 0

$ echo $?
1   # a real CI gate — not a report you must remember to read
Claims go far beyond quotes: "commit X changed file Y" is checked against actual git history; versions against semver ranges; cited receipts are replay-verified. Accumulated receipts become a browsable Evidence Browser with failure triage, regression diff, and claim timelines.

Honest limits · 정직한 한계

  • Faithfulness, not truth. If the source itself is wrong and the citation matches it, that's a pass — it verifies claims against sources, not sources against reality. 출처 자체가 틀리면 잡지 못합니다(충실성 검증이지 진위 판정이 아님).
  • Local-first, evidence-only. No account, no server, nothing leaves your machine unless you opt into the public Rekor anchor. It provides git-based evidence for review — not a compliance guarantee. 계정·서버 없음 — 증거 제공이지 컴플라이언스 보장이 아닙니다.
  • No LLM in the loop. Every verdict is recomputable arithmetic/string/crypto — which is why the same input always gives the same answer. 판정에 모델이 없어 같은 입력이면 언제나 같은 결과.
