# 감사 데모 — AI가 만든 분개(仕訳)를 결정론으로 검증하기

**풀려는 문제.** AI 에이전트가 증빙을 읽고 회계 분개를 자동으로 만들어 주는 시대다. 문제는 그다음이다 — *그 분개를 믿어도 되나?* 대차평균이 맞는지, 합계가 맞는지, 근거가 실제 계약서에 있는지를 사람이 전표마다 다시 검산하면 자동화의 의미가 없다. 그렇다고 "AI가 만들었으니 맞겠지"는 감사가 아니다.

**이 데모가 보여주는 것.** `agent-receipt`는 AI가 만든 분개를 **결정론적 검사**로 대조한다. LLM에게 "이 분개 맞아?"라고 되묻지 않는다 — 산술과 문자열 대조뿐이라 같은 입력이면 언제나 같은 판정이 나오고, 그래서 CI 게이트가 된다.

이 예제의 분개 4건 중 2건은 정상, 2건은 문제가 있다:

| 분개 | 검사 | 결과 |
|------|------|------|
| 1 상품 매출 | 대차평균(차−대=0) · 대변합계 재계산 | ✅ 통과 |
| 2 급여 지급 | 대차평균 | ✅ 통과 |
| **3 비품 구입** | 대차평균 → 차변 500,000 ≠ 대변 450,000 | ❌ **불균형 50,000 반려** |
| **4 지급수수료** | 근거 인용 → 계약은 월 1,500,000, 전표는 2,000,000 | ❌ **날조 근거 반려** |

## 실행

```bash
# 저장소 루트에서
agent-receipt research verify --file examples/audit-journal-entry/entries.md \
  --out examples/audit-journal-entry/receipt.json
#   분개3·4가 걸려 종료코드 1 → CI 가 그대로 막는다
echo "exit=$?"
```

`entries.md`의 모든 숫자·인용은 `source-evidence.md`(분개장·계약서 발췌)에서 온 실측치다 — 검증기가 값을 지어내지 않는다.

## 변조탐지 (감사증적)

검증 결과는 봉인된 영수증으로 남는다. 한 글자만 고쳐도 봉인 재계산이 어긋난다.

```bash
agent-receipt replay --receipt examples/audit-journal-entry/receipt.json
#   receipt.json 을 손으로 고친 뒤 다시 실행하면 → ✗ TAMPERED
```

## 이게 감사·내부통제 언어로 무엇인가

- **대차평균 검사** = 대차평균의 원리(정확성·완전성 어사션)의 자동 재수행(Recalculation).
- **근거 인용 검사** = 전표의 근거가 증빙에 실재하는가(실재성·발생 어사션).
- **봉인·해시체인** = 감사증적(Audit Trail)과 변조탐지(Tamper-evidence).
- **exit 1** = 예방·탐지 통제가 결산 마감/커밋 전에 오류를 막는 게이트.

곧, KPMG 직무기술의 *"AI Agent 기반 연결조정 및 분개 검증 자동화"* 와 *"내부통제(IC)·SOX 영역 AI 솔루션"* 이 하는 일을, 결정론 커널 위에서 시연한 것이다.

## 정직한 경계

대차평균과 근거의 **실재·정합**을 본다. 계정과목 선택이 회계기준상 적정한지, 거래 자체가 실재하는지 같은 **판단**은 감사인의 몫이다 — 이 도구는 그 판단에 쓸 결정론적 증거를 만들 뿐, 판단을 대신하지 않는다.
