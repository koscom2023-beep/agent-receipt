# AI 코딩 에이전트 감사 — "한 일"과 "한 말"을 대조하기

**풀려는 문제.** 이제 Cursor · Claude Code · Copilot 같은 AI 코딩 에이전트가 코드를 바꾸고 "이 커밋으로 이 파일들을 고쳤다", "시킨 범위만 건드렸다", "이 버그를 수정했다"고 **보고**한다. 문제는 그 보고를 믿을 수 있느냐다. git 은 diff 를 보여주지만, **"AI의 주장 ↔ 실제 변경"을 자동으로 대조해 주지는 않는다.** 사람이 매번 커밋을 뒤져 맞추면 자동화의 의미가 없다.

**이 예제가 보여주는 것.** `agent-receipt` 는 AI 코딩 에이전트의 보고를 **실제 git 이력과 결정론으로 대조**한다. 판단은 없고 산술·문자열 대조뿐이라, 같은 입력이면 언제나 같은 판정이 나오고 CI 게이트가 된다.

이 예제의 보고 5건 중 3건은 사실, 2건은 문제가 있다:

| 보고 | 검사 | 결과 |
|------|------|------|
| 커밋이 실재한다 | commit | ✅ verified |
| 그 커밋이 entries.md 를 바꿨다 | fileChanged | ✅ verified |
| 그 diff 에 "대차평균"이 있다 | diffContains | ✅ verified |
| **그 커밋이 src/capture.ts 도 고쳤다** | fileChanged → 실제론 안 건드림 | ❌ **범위 위반 반려** |
| **다른 커밋 해시가 실재한다** | commit → 존재 안 함 | ❌ **환각 반려** |

## 실행

```bash
# 저장소 루트에서
agent-receipt research verify --file examples/ai-coding-audit/agent-report.md
#   거짓 보고 2건이 걸려 종료코드 1 → CI 가 그대로 막는다
echo "exit=$?"
```

보고의 커밋 해시·파일 경로는 이 저장소의 실측값이다 — 검증기가 값을 지어내지 않는다.

## git diff 너머 — 행위 대사(reconcile)

git 은 "무엇이 바뀌었나"만 보여준다. AI 에이전트가 `.env` 를 읽으려다 실패했거나 외부로 전송을 시도한 것은 git 에 안 남는다. `agent-receipt` 의 훅 캡처(`capture --vendor cursor|claude`)는 이 **git 너머 행위**까지 기록하고, `capture show` 의 대사(reconcile)가 **git 변경 ↔ 실제 행위**를 맞춰 "기록에 없는 변경"이나 "읽기·전송만 하고 남긴 것"을 드러낸다.

## 이게 감사·거버넌스 언어로 무엇인가

- **변경통제(Change Control)** — "AI가 승인된 범위만 바꿨나"를 실제 이력으로 대조.
- **완전성·발생 어사션** — 주장한 변경이 실재하는가(fileChanged/commit), 주장한 diff 가 실재하는가(diffContains).
- **감사증적** — 판정을 봉인해 남기고, 변조를 재계산으로 탐지.

곧, EY 한영이 공고에 적은 *"멀티에이전트 개발 워크플로우로 AI 생성 코드·문서·산출물의 품질을 검증/개선"* 을, 결정론 커널 위에서 시연한 것이다. AI 코딩이 표준이 된 지금 "AI 거버넌스"의 실전 부품이다.

## 정직한 경계

git 이력이 진실의 원천이며, 보고에 적힌 **커밋 해시 자체는 자가보고(reported)** 다 — 그 해시가 실재하고 그 변경을 담았는지는 확인하지만, "그 AI 가 정말 그 작업을 했다"는 인과는 보증하지 않는다. 그리고 이 도구는 **주장과 git 의 정합**을 볼 뿐, 코드가 좋은지(품질·보안)는 판단하지 않는다 — 그건 린트·리뷰·테스트의 몫이다.
